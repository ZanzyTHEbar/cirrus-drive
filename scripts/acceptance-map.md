# Linux acceptance contracts

These checks cover different boundaries; one passing check is not a substitute for the others. Use only disposable accounts, servers and data. See [Contributing](../CONTRIBUTING.md) and the scripts for prerequisites.

`cirrus-daemon` is the terminal client (built from `cirrus-cli`); it parses commands and uses the typed `cirrus-client` control library and `cirrus-api` request/reply types. It never starts `cirrus-drive-service`, the separate service binary built from `cirrus-daemon`. Start the service directly; `--no-auto-sync` is a service startup option. For the disposable fault-injection mount labs, build both packages with `cargo build --locked -p cirrus-cli -p cirrus-daemon --features fault-injection`. Rebuild without this feature for installation and packaging checks.

## Space-scoped CLI contracts

- **Explicit Space mounts:** `--mount-space` with a custom path can resume an ordinary mount when the first Graph connection is definitively refused or unreachable, given saved credentials and a matching retained activation and root for that Space. The [account test](../crates/cirrus-account/src/mount_start_tests.rs) checks the transport and retained-proof boundary. The full lab checks ordinary resume after restart; nonread checks that the same retained Space cannot mount without a path during the outage and no default directory is created. Use `--mount-offline-space` for retained read-only access, `--mount-offline-writable-space` for retained editing, and `--unmount-space HTTPS_URL SPACE_ID` for targeted cleanup. The legacy `--mount-status` is gone; match account and Space in the `--mounts` records. Bare `--unmount` is also gone; the [CLI argument test](../crates/cirrus-cli/tests/runtime_check.rs) checks that it is absent from help and rejected as an unknown option without a service. Nonread checks that a wrong Space ID fails with `Space is not mounted` and leaves both mounts and their records unchanged, then verifies that a valid ID unmounts only its target. Preserve negative access, default mountpoint, ownership/identity and targeted recovery assertions.
- **Space-scoped file operations:** There is no persistent Space selection. Use `--ls-space` for ordinary online listing; it first verifies the Space against a fresh authenticated listing. `--ls-offline-space` reads retained metadata without authenticating; it is not evidence of current remote state. Preserve assertions that depend on which request authenticates or publishes an observation. Use explicit `--pin-space`, `--pins-space` and `--unpin-space`; `--pins-space` is local by default, so retain `--check-remote` where the assertion depends on server comparison.
- **Sync and account views:** The full, OIDC and isolation labs use account-wide `--sync`; the full lab also uses `--sync-space` and `--sync-status`. Preserve deliberate account-wide assertions and tests that one Space can continue independently. `--journal` (full/OIDC) is an intentional account view unless a call is explicitly narrowed to `--journal-space`; don't mechanically add Space IDs to account-wide journal, acknowledgement or retained-data views.
